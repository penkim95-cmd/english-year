# 0001. UI 프레임워크 없이 TypeScript와 작은 렌더러로 만든다

- 상태: 채택
- 날짜: 2026-10-23

## 배경

화면은 탭 5개와 전체 화면 클립 플레이어 하나입니다. 상태는 기기에 저장된 두 문서와 화면 상태 한 객체뿐이고, 화면 사이에 공유하는 복잡한 컴포넌트 트리가 없습니다.
첫 버전은 단일 HTML 파일이었고, 문자열로 HTML을 만들며 값마다 `esc()`를 직접 불렀습니다. 이 방식은 빠뜨린 곳 하나가 곧 XSS가 되고, 파일이 커질수록 기능 사이의 경계가 흐려졌습니다.

## 결정

- React·Vue 같은 UI 프레임워크를 쓰지 않습니다.
- 대신 `html` 태그 템플릿(`src/ui/html.ts`)으로 **기본이 이스케이프**인 마크업을 만들고, 화면은 `(app) => SafeHtml` 순수 함수로 씁니다.
- 사용자 동작은 `data-action` 속성과 이벤트 위임으로 처리하고, 각 화면 모듈이 자기 동작 핸들러를 내보냅니다.
- TypeScript strict(`noUncheckedIndexedAccess` 포함)로 콘텐츠·상태 형식을 컴파일 때 확인합니다.

## 결과

- 좋은 점: 런타임 의존이 Anthropic SDK 하나뿐이고 번들이 작습니다. 이스케이프가 기본값이라 빠뜨릴 수 없고, ESLint 규칙이 `innerHTML` 직접 사용을 막습니다. 화면 함수가 순수해서 jsdom에서 그대로 테스트합니다.
- 나쁜 점: 매번 탭 전체를 다시 그려서 입력 중인 요소의 포커스·스크롤을 직접 관리해야 합니다(입력값은 `UiState`에 보관, 대화창은 렌더 후 맨 아래로 스크롤). 스트리밍 출력은 전체 렌더 대신 요소 하나의 `textContent`만 바꿉니다.
- 다시 검토할 때: 화면이 크게 늘거나 부분 갱신이 성능 문제가 되면 Preact나 lit-html 같은 가벼운 렌더러로 옮깁니다. 화면 함수가 이미 상태의 함수라서 옮기는 범위는 `ui/`에 한정됩니다.
